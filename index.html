Общие принципы

  • Невозможные состояния невыразимы в типах
  • Порт и адаптер в гексагоне
  • Секреты не должны попадать в Debug/логи
  • Mutex guard нельзя держать через await
  • Смена корня агрегата в DDD

Настройки панели

  • PanelSettings — агрегат конфигурации
  • SecretToken — newtype с валидацией и редакцией
  • CidrBlock — валидированный IP-диапазон
  • Hot-reload настроек через RwLock
  • Уязвимость: secret_token как голый String (Э-1)

Telegram-бот

  • TelegramNotifier — реализация порта Notifier
  • BotState — обработка команд бота
  • EventBus → Notifier: поток уведомлений
  • Secret<T> из крейта secrecy в TelegramConfig
  • Mutex в run_bot держится через await (Э-2)

Нормализация Client

  • Денормализация: Client живёт внутри Inbound.clients
  • Нормализация: Client — агрегат + junction-таблица
  • Email уже работает как неофициальный первичный ключ
  • Инварианты C2–C5 переезжают без боли, I3 остаётся
  • Единственный реальный риск — слияние данных при миграции

Заметки со значком ◆ — зафиксированные проблемы: у каждой есть номер эпика, и обе уже закрыты рефакторингом (Э-1, Э-2). Второй мозг помнит не только «как устроено», но и «где болело и почему».

Системный контекст

C4 · Level 1

Панель — единственный control-plane. Она хранит состояние в SQLite, толкает конфигурацию в отдельный процесс Xray по gRPC, отдаёт клиентам ссылки-подписки и обменивается клиентами с федеративными нодами.

Слои гексагона

C4 · Level 2 · крейты

Правило зависимостей (06.1): xui-infra / xui-api → xui-app → xui-domain. Домен синхронный и чистый — без tokio/sqlx/tonic и без внешних зависимостей в Cargo.toml. Инфраструктура зависит от абстракций (портов), а не наоборот.

Ключевой поток — применение конфигурации к Xray

runtime · hot-apply

Как изменение (например, новый inbound или новый клиент) доходит до data-plane. Домен решает что делать (ApplyPlan), адаптер исполняет — форматы Xray не протекают глубже xui-infra/xray.

1
xui-api · routes HTTP-хендлер

Принимает запрос, валидирует DTO, вызывает use case. Бизнес-логики в хендлере нет.

2
xui-app · ApplyConfig use case через порт

Собирает желаемое состояние из репозиториев (inbounds + clients) и зовёт порт XrayController. О gRPC ничего не знает.

3
xui-domain · HotDiffCalculator чистая функция

Сравнивает желаемую и текущую конфигурацию → ApplyPlan: NoOp / Hot(ops) / Restart. Каждое правило (H1–H7) покрыто тестом + proptest.

4
xui-infra · handler_config + xray_render адаптер

Hot → per-inbound protobuf через AddInbound, точечные клиенты — через AlterInbound; Restart → рендер полного конфига (policy/api/stats) в файл и перезапуск процесса.

5
Xray-core gRPC :10085

HandlerService применяет изменения. Счётчики трафика (policy statsUser*) читаются обратно планировщиком в следующем тике.

Сквозные аспекты

cross-cutting

Безопасность API

Цепочка middleware перед каждым защищённым маршрутом:

  • TrustMode — источник IP из X-Forwarded-For только для доверенных прокси (дефолт — не доверять)
  • сессии + CSRF (constant-time сравнение) + 2FA (TOTP, state-enum guard)
  • rate-limit (глобальный и per-user), IP-whitelist, CORS из настроек
  • федерация — отдельный периметр по federation_token, не по админской сессии
  • audit-log: вход/выход, неудачные попытки, мутирующие операции

Xray за ACL

JSON-конфиг и gRPC-контракты Xray изолированы в xui-infra/xray* и handler_config/. Домен оперирует типизированной моделью (XrayConfig, ApplyPlan), адаптер переводит её в протокол data-plane. Процесс управляется актором с честным state() через разделяемый атомик.

Типы вместо проверок

Невозможные состояния невыразимы: Protocol, Credentials, Quota, TrustMode, ShortId, Fingerprint, Ss2022Method — enum/newtype с валидацией в TryFrom/parse. StreamSettings::validate проверяет совместимость network↔transport и security↔{tls,reality}. Поля агрегатов приватны, ошибки — enum-значения.

Персистентность и джобы

SQLite через sqlx; составные операции (create+attach, settings) в одной транзакции, списки без N+1. Планировщик тиком собирает трафик, считает онлайн, применяет расписания сброса, квоты, IP-лимиты и алерты. Бэкап/restore с проверкой SQLite-магии и integrity_check.

Подписки
