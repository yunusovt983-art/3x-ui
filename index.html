3x-ui-panel — Rust · DDD

Переписанная на Rust панель управления Xray. Панель оркеструет data-plane (Xray-core за gRPC), но сама трафик не передаёт — «путь A». Гексагон × ограниченные контексты: зависимости направлены строго внутрь, к чистому домену, а код каждого слоя разложен по одним и тем же бизнес-контекстам. Рядом с кодом растёт второй мозг — Zettelkasten-вики с картами тем и атомарными заметками.

Общие принципы

  • Невозможные состояния невыразимы в типах
  • Порт и адаптер в гексагоне
  • Секреты не должны попадать в Debug/логи
  • Mutex guard нельзя держать через await
  • Смена корня агрегата в DDD

Настройки панели

  • PanelSettings — агрегат конфигурации
  • SecretToken — newtype с валидацией и редакцией
  • CidrBlock — валидированный IP-диапазон
  • Hot-reload настроек через RwLock
  • Уязвимость: secret_token как голый String (Э-1)

Telegram-бот

  • TelegramNotifier — реализация порта Notifier
  • BotState — обработка команд бота
  • EventBus → Notifier: поток уведомлений
  • Secret<T> из крейта secrecy в TelegramConfig
  • Mutex в run_bot держится через await (Э-2)

Нормализация Client

  • Денормализация: Client живёт внутри Inbound.clients
  • Нормализация: Client — агрегат + junction-таблица
  • Email уже работает как неофициальный первичный ключ
  • Инварианты C2–C5 переезжают без боли, I3 остаётся
  • Единственный реальный риск — слияние данных при миграции

Заметки со значком ◆ — зафиксированные проблемы: у каждой есть номер эпика, и обе уже закрыты рефакторингом (Э-1, Э-2). Второй мозг помнит не только «как устроено», но и «где болело и почему».

Системный контекст

C4 · Level 1

Панель — единственный control-plane. Она хранит состояние в SQLite, толкает конфигурацию в процесс Xray по gRPC, отдаёт клиентам ссылки-подписки, опрашивает управляемые ноды и обменивается клиентами с peer-панелями. Sidecar-процессы для AmneziaWG и MTProto и платёжный webhook на схеме опущены — они показаны на уровне L0 выше.

Слои гексагона

C4 · Level 2 · девять крейтов

Правило зависимостей: api / infra → app → domain. Домен синхронный и чистый — без tokio/sqlx/tonic и без внешних зависимостей в Cargo.toml. Инфраструктура разделена на общее ядро, три листовых адаптера, которые не видят друг друга, и фасад с интеграциями. HTTP-слой про инфраструктуру не знает: их связывает только composition root.

Ключевой поток — применение конфигурации к Xray

runtime · hot-apply

Как изменение (например, новый inbound или новый клиент) доходит до data-plane. Домен решает что делать (ApplyPlan), адаптер исполняет — форматы Xray не выходят за крейт xui-infra-xray.

1
xui-api · routes HTTP-хендлер

Принимает запрос, валидирует DTO, вызывает сценарий. Бизнес-логики в хендлере нет.

2
xui-app · engine · ApplyConfig сценарий через порты

Берёт общий apply_session, читает желаемое состояние через узкий порт InboundClientSource и зовёт XrayController. О gRPC ничего не знает. Если Xray поставлен на паузу администратором — возвращает NoOp.

3
xui-domain · HotDiffCalculator чистая функция

Сравнивает желаемую и применённую конфигурацию → ApplyPlan: NoOp / Hot(ops) / Restart. Клиенты сравниваются до конфигов; для протоколов без правки пользователей на месте план пересоздаёт один inbound.

4
xui-infra-xray · xray_grpc + xray_render адаптер

Hot → RemoveInbound, AlterInbound, AddInbound; любая ошибка gRPC эскалируется в Restart. Restart → кандидат конфига проходит xray -test, пишется атомарно с правами 0600, счётчики переносятся через рестарт.

5
Xray-core gRPC :10085

HandlerService применяет изменения. Счётчики трафика читаются обратно планировщиком в следующем тике и в той же транзакции применяют квоту и срок клиента.

Сквозные аспекты

cross-cutting

Безопасность API

Слои перед защищённым маршрутом — в порядке исполнения:

  • security headers с CSP-nonce, CORS по списку origin
  • сессия в SQLite; session_epoch гасит сессии после смены пароля или 2FA
  • rate-limit на пользователя или IP, строгий лимит на вход и чувствительные операции
  • IP-whitelist; TrustMode — X-Forwarded-For только от доверенного прокси
  • Bearer API-токен с шестью областями либо cookie + CSRF
  • reauth (пароль + TOTP) для смены пароля и выпуска токенов; audit-log

Xray за ACL

JSON-конфиг и gRPC-контракты Xray изолированы в крейте xui-infra-xray. Домен оперирует типизированной моделью (XrayConfig, ApplyPlan), адаптер переводит её в протокол data-plane. Процессом управляет актор; администратор может остановить, перезапустить и обновить Xray из панели — обновление сверяет SHA-256 и откатывается при неудаче.

Типы вместо проверок

Невозможные состояния невыразимы: Protocol, Credentials, Quota, ExpiryTime, IpLimit, TrustMode, ApiScopes — enum/newtype с валидацией в parse. «Магического нуля» нет: безлимит — отдельный вариант, а не 0. Поля агрегатов приватны, ошибки — enum-значения.

Узкие порты

Читающий сценарий не получает CRUD-контракт: ApplyConfig видит только InboundClientSource, сборщик трафика — TrafficRecorder, проверка истечения — ExpiryStore. Существующие адаптеры подключаются статическим мостом impl<T: Широкий> Узкий for T — без boxing и новых аллокаций.

Персистентность и джобы

SQLite через sqlx: 43 миграции, репозитории разложены по контекстам. Счётчик трафика, запуск срока и блокировка по квоте фиксируются одной транзакцией. Цикл обслуживания принадлежит слою приложения и тестируется без Tokio и SQLite. Бэкап — VACUUM INTO, восстановление проверяет целостность, внешние ключи и историю миграций.

События и плагины

Сценарии публикуют DomainEvent после commit; на шину подписаны лог, Telegram (через cooldown), SSE-поток для браузера и плагины. Каждый NotifierPlugin получает собственную подписку, поэтому упавший или медленный плагин не задерживает остальных.

Подписки

Единый профиль исходящего соединения → несколько форматов: base64-список ссылок, Clash YAML, JSON, sing-box outbounds, конфиг WireGuard и AmneziaWG. Шаблоны remark с переменными. Формат — публичный контракт с клиентским приложением: общая фикстура проверяется тестами обеих сторон.

Web-UI

React 19 + Router 7 + TypeScript 6 + Vite 8 + Tailwind 4, встраивается в бинарь через rust_embed. Типы API генерируются из OpenAPI, и гейт не даёт им разойтись со схемой бэкенда. Живые обновления — EventSource поверх SSE; библиотек состояния и запросов нет.

Гейт и CI

Один скрипт для людей, агентных сессий, git-хука и CI: fmt, сборка и тесты веба, сверка типов API, clippy -D warnings, cargo test, release-сборка, Go-sidecar и AST-индекс. Тест архитектуры проверяет граф зависимостей крейтов и раскладку каталогов по контекстам. Красный гейт — не коммитим.

Ноды и федерация

Нода — такая же панель со своим Xray. Мастер ходит к ней по REST с токеном области Node, проверяя цепочку или pin сертификата: heartbeat, сбор трафика, отправка набора клиентов. Исходящие адреса проходят SSRF-политику домена. Обмен между равноправными панелями — отдельный путь с собственным токеном.
